# TASK: Spring Boot Resource Server JWE Decryption & Security Configuration

## 1. Objective
Configure the Spring Boot application to act as a stateless OAuth2 Resource Server. It must successfully receive, decrypt, and validate the 5-part JWE (JSON Web Encryption) Access Token generated by the Keycloak SPI.

## 2. Technical Stack & Constraints
- **Java:** 25
- **Framework:** Spring Boot 4, Spring Security 7
- **Base Package:** `com.archcore.security`
- **Strict Compliance:** Must strictly adhere to `RULES.md` (Stateless, Lombok mandatory, strictly API-only).

## 3. Implementation Steps
- **Environment & Profile Strategy (Dev vs Prod):**
    - Implement a configuration properties class (e.g., `@ConfigurationProperties(prefix = "archcore.security.jwe")`) to manage key locations.
    - **Dev Profile (`application-dev.yml`):** Configure the app to load a dummy private key from the classpath or a local file for seamless local development.
    - **Prod Profile (`application-prod.yml`):** Configure the app to strictly load the private key via Environment Variables (e.g., `${JWE_PRIVATE_KEY_PATH}` or direct key injection) ensuring zero hardcoded secrets.
- **JWE Decoder Configuration:**
    - Spring Security 7 defaults to JWS. Implement a custom `JwtDecoder` (leveraging Nimbus JOSE+JWT) that processes the JWE decryption using the private key loaded from the environment profile, before parsing the JWT claims.
- **SecurityFilterChain Setup:**
    - Configure HTTP security to be entirely stateless (`SessionCreationPolicy.STATELESS`).
    - Integrate the custom JWE Decoder into the `oauth2ResourceServer` configuration.
    - Disable CSRF.
- **Unit Testing:**
    - Write JUnit 5 and Mockito tests to verify the custom JWE decoder logic. Mock the environment properties to test both dev-like and prod-like key loading scenarios.
