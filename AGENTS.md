# Autonomous Agents Overview

This document outlines the architecture and responsibilities of the autonomous AI agents utilized within the OpenSpec framework for managing and executing the `enterprise-saas-kit` project.

These agents are designed to handle specific domains of the software development lifecycle, ensuring that the specification remains the single source of truth while automating code modifications and reviews.

## 0. Global Directive: `.opencode/RULES.md`
**CRITICAL:** All agents described in this document operate under the strict jurisdiction of the `.opencode/RULES.md` file. This global ruleset acts as the ultimate constitution for architectural boundaries, security protocols, clean code standards, and execution limits. **No agent is permitted to override, bypass, or ignore the constraints defined in `.opencode/RULES.md`.**

## 0.1 Architecture Context: `.opencode/ARCHITECTURE.md`
**MANDATORY:** Every agent MUST read `.opencode/ARCHITECTURE.md` at the start of each session. This file contains:
- Quick reference summary (stack, patterns, current state)
- Key rules and constraints

**Detailed docs are split for token optimization:**
- `.opencode/arch/auth.md` — Authentication & JWE SPI details
- `.opencode/arch/infra.md` — Docker & infrastructure
- `.opencode/arch/config.md` — Configuration flow & templating

**Why this matters:** A new session has no memory of past work. ARCHITECTURE.md is the bridge. Before making ANY change, agents must understand what exists and why it was built that way. After completing a task, agents MUST update ARCHITECTURE.md to reflect new decisions, components, or patterns.

## 1. Specification Agent (`spec-agent`)

The core intelligence responsible for maintaining the structural integrity and logic of the project's specification files.

*   **Role:** Architect & Requirements Analyst
*   **Responsibilities:**
    *   Parses incoming user requirements or feature requests.
    *   Translates requirements into formal Spec-Driven Development formats.
    *   Ensures that new requirements do not conflict with the architectural constraints defined in `.opencode/RULES.md` (e.g., maintaining the Modular Monolith structure, strict separation of Keycloak for Identity Management, and locked technology versions).
    *   Generates and updates the core `.spec` files (e.g., `api.spec.yaml`, `auth.spec.yaml`).
*   **Triggers:** Activated when a new high-level requirement is introduced or when a structural change is needed in the business logic.

## 2. Code Generation Agent (`codegen-agent`)

The execution engine that translates formal specifications into concrete, production-ready code.

*   **Role:** Full-Stack Developer
*   **Responsibilities:**
    *   **Execution Limits:** Operates strictly within the scope of the active task file in `.tasks/`. Cannot modify files outside this scope on its own initiative.
    *   Reads the updated `.spec` files generated by the `spec-agent`.
    *   Generates Spring Boot controllers, services, and repository layers adhering strictly to **Clean Code principles** (SRP, DRY, SOLID) as mandated by `RULES.md`.
    *   Implements secure Keycloak token validation (Bearer Token approach) without writing custom authentication logic.
    *   **MCP Integration:** Dynamically fetches up-to-date documentation for Java 25, Spring Boot 4, and Keycloak via MCP tools before generating complex configurations.
    *   Scaffolds the "dumb" frontend components based on the 5-dollar UI template structure, strictly avoiding any refactoring for performance or clean code on the UI side.
    *   **Post-Task Reporting:** Generates a mandatory execution log detailing applied software design patterns and architectural rationale after completing a task.
*   **Triggers:** Activated whenever a `.spec` file is updated and committed.

## 3. Infrastructure & Deployment Agent (`infra-agent`)

The operations specialist ensuring the application is deployed correctly and securely.

*   **Role:** DevOps Engineer
*   **Responsibilities:**
    *   Maintains and updates `docker-compose.yml` for local development (coordinating PostgreSQL, Keycloak, and the Spring Boot API).
    *   Generates and validates Kubernetes manifests (Deployments, Services, Ingress) and Flyway/Liquibase migration scripts.
    *   Ensures ArgoCD application definitions are in sync with the desired state of the repository.
    *   **Environment Compliance:** Ensures all generated build files (e.g., Maven `settings.xml` configurations) strictly point to the mandated local JDK 25 path defined in `RULES.md`.
    *   **MCP Integration:** Uses documentation fetchers for Keycloak container configurations and environment variables before modifying infrastructure files.
*   **Triggers:** Activated when architectural changes require new infrastructure components (e.g., adding a Redis cache) or when deployment configurations are modified.

## 4. Security & Audit Agent (`security-agent`)

The gatekeeper that ensures the generated code and infrastructure adhere to the defined security standards.

*   **Role:** Security Auditor & Compliance Checker
*   **Responsibilities:**
    *   Scans generated Spring Boot code to ensure XSS protection (Jackson configurations) and CSRF mitigation (Bearer token validation) are correctly implemented as per `RULES.md`.
    *   Validates CORS configurations to prevent wildcard origins.
    *   Checks Bucket4j rate limiting implementations.
    *   Verifies that no plain-text passwords or secrets are hardcoded in the infrastructure files or database schemas.
    *   **VCS & Ignored Files Audit:** Ensures that no forbidden files (e.g., `.env`, `*.pem`, `target/`, `.idea/`) are committed, enforcing strict `.gitignore` compliance as dictated by `RULES.md`.
*   **Triggers:** Runs automatically as a pre-commit hook or during the CI pipeline on all generated code before it is merged.

## Execution Workflow

1.  **Context Loading:** Agent reads `.opencode/ARCHITECTURE.md` to understand current project state.
2.  **Requirement Input:** User provides a natural language requirement to the `spec-agent`.
3.  **Specification Update:** `spec-agent` translates this into a formal `.spec` update, validating against `.opencode/RULES.md`.
4.  **Code Synthesis:** `codegen-agent` and `infra-agent` read the new spec and generate the corresponding application code and infrastructure files, utilizing MCP tools for accuracy.
5.  **Logging & Rationale:** `codegen-agent` outputs its execution log detailing applied patterns.
6.  **Security Review:** `security-agent` reviews the output against established enterprise constraints and VCS rules.
7.  **Architecture Update:** Agent updates `.opencode/ARCHITECTURE.md` to reflect new decisions, components, or patterns added.
8.  **Finalization:** Approved code is auto-added to Git and ready for manual review or automated deployment.
